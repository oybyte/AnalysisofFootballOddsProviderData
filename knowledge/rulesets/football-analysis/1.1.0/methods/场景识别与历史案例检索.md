# 场景识别与历史案例检索

## 目的和适用范围

把当前观察登记为可反证场景，再检索历史候选；不把关键词相似宣称为语义等价。

## 术语

- 场景类型描述结构而非结局
- 场景实例属于单场观察
- 候选案例必须解释差异

## 必需输入

- 有效规则回执
- 赛前事实哈希
- 盘赔时序
- 场景白名单
- 可用案例语料

## 数据质量要求

- 所有事实必须记录来源、采集时间和时区；不得用盘口反推不存在的伤停或资金事实。
- 原始盘口、水位和机构文字保留原字符串；无法确认口径时登记冲突。
- 历史案例只有 `prematch_verified` 且时间边界可证明时才可能进入统计。

## 逐步执行过程

1. 从无意图事实识别结构
2. 匹配场景类型或 unclassified
3. 填写 A/B 假设
4. 生成元数据与关键词查询
5. 执行 as_of 和目标排除
6. 记录选中与排除候选

## 判断矩阵

| 条件 | 动作 | 边界 |
|---|---|---|
| 匹配已有类型 | 登记实例和触发点 | 不继承历史结局 |
| 新结构 | 使用 unclassified | 禁止强行套规则 |
| 无明确结构 | 记录 no_scenario_reason | 仍可 pass |

## 双向假设

- 假设 A：历史候选共享可比较的盘口结构和关键条件。
- 假设 B：候选仅共享球队或关键词，机制不同。
- 两个假设都必须填写支持证据、反证和锁定前可观察的区分条件。

## 区分触发条件

- 同联赛/赛季
- 相同盘口前置历史
- 相同市场冲突
- 反例是否存在

## 跨市场冲突优先级

1. 当前事实高于案例
2. 场景前置历史高于最终形态
3. 已复盘且时间有效高于 mixed 案例

## 失效和 Pass 条件

- 规则回执无效
- 场景未登记
- 候选时间晚于 as_of
- 案例只有赛后叙述

满足任一关键失效条件且无法在截止前补齐时，主市场应为 `pass`；不得用降低措辞强度代替 pass。
