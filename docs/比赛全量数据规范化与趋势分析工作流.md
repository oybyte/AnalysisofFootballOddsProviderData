# 比赛全量数据规范化与趋势分析工作流

## 1. 范围

`MatchDataBundleV1` 统一承载比赛身份、澳门让球详细时序、多机构让球/欧赔/大小球/凯利初即盘，以及半场和全场比分。场地和天气可空；比赛双方、联赛代码、带时区开赛时间不可缺失。无法唯一绑定 Match 时停止，不推测身份。

权威数据采用追加式台账：

- `knowledge/market-observations/events.jsonl`
- `knowledge/market-observations/source-links.jsonl`
- `knowledge/match-facts/events.jsonl`
- `knowledge/match-results/events.jsonl`

Match Front Matter 是兼容投影，`ai/analytics/football.sqlite3` 是可重建查询投影，均不替代台账。

`historical_finished` Match 不会在正文中回填赛前事实表、推演或结论，也不会把赛后归档的 `market_data` 从“用户材料归档”提升到正式赛前章节。即使完整盘口已规范化，人工查看该场数据应使用 `market observations show-series --match MATCH_PATH`、对应的 Bundle 或 Analytics 查询；这不是数据缺失，也不表示可以补建锁定或结算。

## 2. 完赛全量入口

```powershell
.\scripts\odds-journal.ps1 journal finish `
  --bundle knowledge/match-data-bundles/MATCH.yml `
  --match matches/YYYY/MM/MATCH.md `
  --actor lcz `
  --received-at "2026-08-04T08:00:00+08:00"
```

命令按三个独立阶段执行：

1. 将 bundle 原文按内容哈希归档到 `raw/matches/<match_id>/match-data-bundles/`。
2. 原子写入基础事实、市场观测、来源映射和赛果观测；失败时整批市场写入回滚，原文归档保留。
3. 单独执行现有赛果生命周期。`locked` 可正常 `finish`；未锁定记录只归档，只有 `lcz --confirm-historical` 才允许历史完结。已是 `historical_finished` 且比分一致时返回 `already_finished`。

重复执行同一 bundle 不重复追加观测或赛果。不同来源引用同一自然观测时只增加 source link。

## 3. 时间和去重

三个时间字段不可互换：

- `observed_at`：盘口页面显示的报价时间。
- `source_captured_at`：截图或材料形成时间。
- `received_at`：材料进入仓库的时间。

精确时间自然键由比赛、机构、市场、盘口角色和 `observed_at` 组成。阶段端点自然键使用 `phase_hint + capture_batch_id`。同键同值复用观测；同键异值保留双方并形成冲突；不同时间即使数值相同也新增观测。

冲突查询与处置：

```powershell
.\scripts\odds-journal.ps1 market observations conflicts --all
.\scripts\odds-journal.ps1 market observations resolve-conflict `
  --conflict-group-id ID --status confirmed_source `
  --observation-id OBSERVATION_ID --reason "来源核验说明" --actor lcz
```

处置同样是追加事件，不删除冲突原值。

## 4. 趋势特征

```powershell
.\scripts\odds-journal.ps1 market observations show-series --match MATCH_PATH
```

`MarketFeatureSnapshotV2` 输出：完整盘口路径、同档水位序列、升退盘步数、反转、最大回撤、趋势纯度、临场 60 分钟节点、多机构方向矩阵、头部机构标记、时间精度、冲突和排除原因。跨档只比较盘口变化，不直接相减水位。

只有初盘/即盘时保存 `phase_only` 退化端点。端点相同只输出 `endpoint_change: 0`、`intermediate_path_status: unknown` 和 `stable_throughout: unverified`；只有完整精确时序全部无变化才可声明稳定。

`normalization_eligible`、`prediction_eligible` 和 `retrospective_validation_eligible` 分别计算。赛后补交资料可以展示完整规范化趋势，但不能回填历史正式预测；未认证资料也不进入规则统计分母。

## 5. 正式轨与实验轨

已发布 `football-analysis@1.8.0` 使用 Contract 7 独立评估每个市场；总进球或比分证据不足时必须 `pass`，不影响其他已评估市场。新观测只在没有分析回执的 draft/tracking Match 上生成兼容投影；分析开始后新增数据不会改变本次输入。

存在规范化观测时，`agent start` 生成活动实验对应的 `ExperimentAnalysisReceiptV4`，冻结观测集合哈希、`MarketFeatureSnapshotV2`、RuleBuildManifest 和提示/研究规则集合。`1.7.0` 实验可读取精确时序和 phase-only 端点，但时间窗口规则只接受 exact 节点。实验结果不驱动正式锁定、结算或正式评价。

## 6. 回填与查询

```powershell
.\scripts\odds-journal.ps1 market observations inventory
.\scripts\odds-journal.ps1 market observations backfill --max-matches 5 --max-observations 5000
.\scripts\odds-journal.ps1 analytics build
.\scripts\odds-journal.ps1 analytics validate
```

旧 `MarketSnapshot` 回填同样执行自然键去重。默认每批最多 5 场、5,000 条；中断后重复执行可恢复。Analytics V4 包含事实、观测、来源、冲突、序列节点、趋势特征、赛果、覆盖与实验提示投影，数据库通过完整性检查后原子替换。
