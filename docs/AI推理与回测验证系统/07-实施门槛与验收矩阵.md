# 实施门槛与验收矩阵

## 实施顺序（与演进路线对齐）

### 第一阶段准备（实施 Phase 0-4，预计 4-6 周开发）

1. **已完成：Phase 0+1 确定性基础**
   - 实现 `BacktestDatasetManifest`、标签延迟物化、代码化结算
   - 回放冻结赛前输入并重建 Outlook，建立可复验的历史结论研究基线；不重跑当前 `1.8.0` 规则
   - 验收：时间泄漏测试、亚盘结算测试全部通过

2. **已完成：Phase 2 sandbox + pilot 基础**
   - 实现 fake provider、sandbox 配置、Prompt 模板（五阶段）
   - 实现真实配置快照、出站策略、预算门禁
   - 验收：sandbox 与 FakeProvider 已跑通；真实 LLM adapter 属于未启用的后续安全批准范围

3. **已完成：Phase 4/5 confirmatory 与人工衔接基础**
   - 实现 Primary 占位、Study 预注册、Outcome 生成
   - 实现 Analytics 投影表、对比报告
   - 验收：Study、Primary 占位、Outcome 与人工处置链路可由 FakeProvider 验证；真实 provider 研究仍需独立批准

### 第一阶段运行（积累 30 场对比数据，预计 15 周）

4. **每周 2 场比赛**，同时运行：
   - 正式轨（规则 1.8.0）
   - AI confirmatory Primary（相同数据）

5. **每 10 场查看中期报告**：
   ```powershell
   odds-journal ai experiment report --study STUDY_ID
   ```

6. **30 场后里程碑**：
   - 产出"规则 vs AI 对比报告"
   - 决策：是否进入第二阶段（提炼新规则）

### 第二阶段（如果第一阶段发现 AI 有价值，预计 4 个月）

7. **人工分析 AI 成功案例**（Phase 5）
   - 提炼 1-3 个可代码化的规则
   - 走 rules intake 流程，由 lcz 创建并激活新的实验 proposal revision；不得复用正式 proposal 的版本号

8. **三轨对比验证**（又 30 场）
   - 当前正式基线
   - 新实验 proposal revision
   - AI 实验轨

9. **60 场后决策**：新规则是否正式发布？

### 可选项（按需实施）

10. **Phase 3 案例重排**：实现已存在但默认停用；只有研究门槛满足并由 lcz 批准配置后才可运行

每个阶段必须可单独停用或重建其新建投影，不改写已发布规则、历史回执、已锁定比赛或正式统计。

## 必须通过的验收

| 类别 | 验收行为 |
|---|---|
| 正式轨隔离 | AI 开/关、成功/失败时，正式 Outlook、Lock、Settlement、Review 与正式统计哈希不变 |
| 回放资格 | 历史复现拒绝 cutoff 后入库观测；反事实模式只接受已认证的赛前证据 |
| 标签隔离 | Prediction 封存前不生成 Label Manifest，预测进程不可读赛果或赛后投影 |
| Sandbox | 不能读真实比赛、案例、凭据或网络，不能写权威 AI 台账 |
| 运行降级 | 可选模块失败会记录 capability profile；核心预测或 EvidenceRef 失败不生成 Outlook |
| Primary/Study | 名额不可替换，赛后不可补建，只有赛前预注册的 confirmatory Study 可入分母 |
| 结算与统计 | 亚盘全赢/半赢/走盘/半输/全输及四分之一盘通过；pass 为 not_evaluated；完整/降级 capability 分层 |
| 出站门禁 | Prompt、Schema、EvidenceRef、provider 模型、价格或 payload 字段不匹配时 fail closed |
| 兼容 | Schema 1-7、`football-analysis@1.8.0`、`1.7.0` 实验产物和历史回执仍可读、可复验 |

### 未来研究关键验收（真实 provider 获批且完成 30 场预注册 cohort 后）

除上述技术验收外，第一阶段结束时必须能回答以下业务问题：

| 问题 | 数据来源 | 通过标准 |
|------|----------|----------|
| 同一合资格 cohort 的冻结 Outlook 表现如何？ | Phase 1 确定性回放报告 | 各市场有明确基线和不确定性区间；不得外推为当前规则真实准确率 |
| AI 在哪些市场有优势？ | Phase 4 对比报告 | 至少 1 个市场准确率差异 >5% |
| AI 的成本可接受吗？ | AI 运行日志（token 用量） | 单场成本 <$0.50 |
| 是否值得进入第二阶段？ | 综合评估 | AI 在某市场优势 >10% 且样本 >=30 |

**如果 30 场后 AI 在所有市场都不如规则**：
- 选项 A：停止 AI 实验，继续优化规则
- 选项 B：调整 AI 配置（Prompt/模型），再试 30 场
- 选项 C：改变 AI 角色（从"独立预测"改为"审查规则"）

上述阈值是未来预注册研究的决策条件，不是当前运行结果。第一阶段的目标是**建立发现 AI 是否有价值的受控能力**，而不是"让 AI 立即上线"。

### 受信 Prompt 与策略（须加入 `ai/desktop-agent-manifest.yml` 白名单）

**Prompt 模板**（`ai/ai-experiment-prompts/{config_version}/`）

- `stage1_facts.md` — 盘口事实梳理
- `stage2_rules.md` — 规则引擎结果解读
- `stage3_cases.md` — 历史案例对比
- `stage4_prediction.md` — 综合推理与预测（需支持降级分支）
- `stage5_risk.md` — 风险与观测清单

**出站策略**（`ai/ai-experiment-policies/`）

- `{provider_id}-outbound-policy.yml` — 每个 provider 的出站数据策略
- 默认 `network_access: deny`，启用需 lcz 批准

### 权威产物目录结构

### 复用现有基础设施

以下能力无需新增，直接复用现有代码：

| 能力 | 现有模块 | 复用方式 |
|------|---------|---------|
| canonical JSON + SHA-256 | `ledger.py` | `canonical_json()`, `sha256_json()` |
| 追加式 JSONL 台账 | `ledger.py` | `append_payloads()`, `read_ledger()`, `LedgerEvent` |
| canonical text + SHA-256 | `rules.py` | `canonical_text()`, `sha256_text()`, `sha256_file()` |
| 观测资格判定 | `observations.py` | `_eligibility()` 已产出 `prediction_eligible` / `retrospective_validation_eligible` |
| 特征快照 | `observations.py` | `market_feature_snapshot()` 已产出 `feature_snapshot_sha256` |
| 案例检索 | `case_retrieval.py` | `retrieve_cases()` 产出 `CaseReceipt` |
| Schema 生成与校验 | `schemas.py` | `SCHEMA_MODELS` 字典 + `build_schemas()` + `schemas check` |
| Analytics 重建 | `analytics.py` | `build_analytics()` 已支持可删除重建投影 |

**估算工作量**：
- 新增 Schema：约 21 个（参考现有 14 个 `experiment-*` schema）
- 新增源代码：约 5 个模块（2000-3000 行/模块）
- 新增 CLI 命令：约 15 个
- 新增 Analytics 表：约 11 张
- 新增测试：约 200-300 个测试用例

当前实现已覆盖上述阶段的受控接口和 FakeProvider。真实 provider、活动 AI 配置、案例重排和任何规则发布均保持关闭，必须走各自的人工批准门禁。
