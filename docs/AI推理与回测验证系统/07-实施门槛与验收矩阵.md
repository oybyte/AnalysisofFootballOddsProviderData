# 实施门槛与验收矩阵

## 实施顺序

1. **确定性基础**：实现 Phase 0/1、完整 Dataset Manifest、标签延迟物化和代码化结算。未通过时间泄漏和结算回归前，不实现真实 provider。
2. **离线 sandbox**：实现 fake provider、`AISandboxConfigV1`、Prompt/Schema 夹具和网络阻断。这一阶段只验证运行通路，不产生真实研究结论。
3. **Pilot**：实现受批准的配置快照、出站策略、预算门禁、模块降级和 diagnostic 运行。对真实赛前数据只作可运行性评估。
4. **Confirmatory**：实现 Primary 占位、Study 预注册、Outcome/Disposition、Analytics 投影和分层报告。
5. **案例重排与演进**：实现 Phase 3 的受限重排，最后才将研究模式送入现有 Rule Intake 管道。

每个阶段必须可单独停用或重建其新建投影，不改写已发布规则、历史回执、已锁定比赛或正式统计。

## 必须通过的验收

| 类别 | 验收行为 |
|---|---|
| 正式轨隔离 | AI 开/关、成功/失败时，正式 Outlook、Lock、Settlement、Review 与正式统计哈希不变 |
| 回放资格 | 历史复现拒绝 cutoff 后入库观测；反事实模式只接受已认证的赛前证据 |
| 标签隔离 | Prediction 封存前不生成 Label Manifest，预测进程不可读赛果或赛后投影 |
| Sandbox | 不能读真实比赛、案例、凭据或网络，不能写权威 AI 台账 |
| 运行降级 | 可选模块失败会记录 capability profile；核心预测或 EvidenceRef 失败不生成 Outlook |
| Primary/Study | 名额不可替换，赛后不可补建，只有赛前预注册的 confirmatory Study 可入分母 |
| 结算与统计 | 亚盘全赢/半赢/走盘/半输/全输及四分之一盘通过；pass 为 not_evaluated；完整/降级 capability 分层 |
| 出站门禁 | Prompt、Schema、EvidenceRef、provider 模型、价格或 payload 字段不匹配时 fail closed |
| 兼容 | Schema 1-7、`football-analysis@1.8.0`、`1.7.0` 实验产物和历史回执仍可读、可复验 |

## 新增契约与存储清单

实现时新增 Schema 包括配置快照/激活事件、sandbox 配置、Primary claim、阶段事件、运行 manifest、Receipt/Bundle/Outlook/Outcome/Disposition/Study、出站策略、provider 价格快照、回放数据集/标签/预测/Outcome manifest。

源代码模块预计为 `ai_experiment.py`、`ai_experiment_config.py`、`backtest.py`、`case_rerank.py` 和 `llm_provider.py`。受信 Prompt 位于 `ai/ai-experiment-prompts/{config_version}/`，出站策略位于 `ai/ai-experiment-policies/`，并加入 desktop manifest 白名单。运行和回放产物的完整路径以 Phase 1 和 Phase 2 文档为准。
