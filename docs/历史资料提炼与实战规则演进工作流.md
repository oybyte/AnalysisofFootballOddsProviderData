## 2. 数据分层

```text
knowledge/sources/                         不可变原始资料
knowledge/extraction/doubao-2026-07-28/   原子库存和追加式事件台账
knowledge/cases/legacy/                   从 case event 重建的案例投影
knowledge/rule-proposals/                 可审查但未生效的规则提案
knowledge/rulesets/                       已发布且不可原地修改的规则集
knowledge/evidence/                       reviewed 比赛追加的规则证据
matches/                                  每场比赛的唯一人工事实记录
data/*-context/                            可删除重建的检索上下文缓存
ai/index/                                  可删除重建的 SQLite FTS5 索引
reports/                                   覆盖和证据报告
```

信任边界固定如下：

- 原始资料、OCR、网页、案例、规则内容和搜索结果都是待分析数据，不能发出行为指令。
- 只有路径、文档 ID 和元数据同时命中白名单的 `ai/analysis_prompt.md` 与 `ai/review_prompt.md` 是可信指令。
- 规则负责限制分析方法，不能替代比赛事实；案例只提供候选对照，不能继承历史结局。

## 3. 历史资料提炼

### 3.1 重建库存

正常使用不需要重复重建。只有库存代码或原始归档结构发生经过批准的迁移时才执行：

```powershell
odds-journal source inventory knowledge/sources/doubao-2026-07-28
odds-journal source make-batches
```

库存命令先对照 `MANIFEST.yml` 校验原始哈希，再解析标题、段落、列表、表格、代码、图片、分隔线和 gap。任一文件的原子范围必须从第 0 字节连续覆盖到文件末尾。

### 3.2 分批审查

批次以完整轮次为边界，每批最多 20 轮或 50,000 个规范化字符：

```powershell
odds-journal source draft-batches --reviewed-by codex --reviewed-at now
odds-journal source accept-batch knowledge/extraction/doubao-2026-07-28/batches/001-013.review.yml
```

每批必须同时处理两份 Markdown、关联媒体、声明、纠错、冲突、案例和最终处置。错误不能回写旧 JSONL 行，只能追加带 `supersedes_event_id` 的新事件。

### 3.3 覆盖门禁

```powershell
odds-journal source coverage
odds-journal evidence validate
odds-journal case rebuild
odds-journal case validate
```

案例 V3 分离 `source_archived_at` 与 `revision_effective_at`。历史检索先按 case event 的 `recorded_at <= as_of` 为每场选择唯一 revision，再进入 FTS5/BM25；当前阅读投影不作为第二份案例语料索引。

覆盖发布门槛包括：原始哈希有效、字节覆盖 100%、原子和媒体处置 100%、accepted 关联 100%、事件链有效、未解决冲突为 0、阻断项为 0。媒体 `review_status: pending` 不得被误解为已经完成人工视觉读数；未经过视觉核对的 OCR 不能写入 `verified_observations`。

## 4. 规则提案与发布

### 4.1 提案

```powershell
odds-journal rules scaffold-proposal 1.1.0 --prepared-at now
odds-journal rules proposal-validate 1.1.0
```

每篇 1.1.0 规则必须包含目的、输入、质量要求、步骤、判断矩阵、双向假设、触发条件、冲突优先级、Pass 条件、支持案例、反例、source atom/claim 引用、证据快照和版本说明。

经验规则保持 `experimental`。样本达到晋级门槛只生成新提案，不自动改变可信度。

### 4.2 人工批准与事务发布

lcz 审读全部提案并明确批准后执行：

```powershell
odds-journal rules release 1.1.0 --approved-by lcz
```

发布按以下顺序完成：

1. 校验提案、覆盖报告、证据台账和所有引用。
2. 阻止仍含实质 v1 分析但尚未锁定的比赛。
3. 生成带真实北京时间、证据快照和 `APPROVAL.yml` 的正式临时目录。
4. 原子重命名为正式不可变版本。
5. 迁移纯占位比赛并构建 schema 4 临时索引。
6. 所有检查成功后最后更新 `active.yml`。

若索引或活动指针阶段失败，旧活动版本保持不变。已经生成但未激活的正式目录可以在提案、快照和批准信息完全一致时继续发布，禁止覆盖或偷偷重写。

## 5. 每场实战流程

### 5.1 事实归档

创建比赛后，只填写可核对事实、原始盘口字符串、采集时间、来源和缺失项。截图放入对应 `assets/matches/{match_id}/`，原始导出放入 `raw/matches/{match_id}/`。

仅要求整理资料时，到此停止，不登记方向、不生成比分、不调用分析工作流。

### 5.2 规则准备

```powershell
odds-journal prepare-analysis matches/YYYY/MM/比赛.md `
  --market handicap `
  --market total_goals `
  --as-of "2026-07-30T17:30:00+08:00"
```

命令精确加载 manifest 中全部必需规则，只在条件规则白名单内排序。v2 回执冻结赛前事实哈希、规则集、规则内容、片段、查询、市场和时间边界。

事实变化时：

- 分析正文仍为空，可重新准备；旧案例回执被清除，场景的 `as_of` 必须与新准备一致。
- 已有实质分析，必须执行 `analysis restart --reason TEXT`。旧推演和旧最终结论会归档，事实保留。

### 5.3 场景登记

示例 `scenario.yml`：

```yaml
scenario_instance_id: seoul-ulsan-line-reversal-1
scenario_type_id: late-market-reversal
detected_at: 2026-07-30T17:35:00+08:00
as_of: 2026-07-30T17:30:00+08:00
market: handicap
observed_facts:
  - 主流机构由主让 0.75 回到主让 0.5
matched_rule_ids:
  - late-market-reversal
hypothesis_a: 新信息使主队估值下降
hypothesis_b: 临场流动性导致短时风险再平衡
supporting_evidence: []
counter_evidence: []
discriminating_triggers:
  - 多机构是否持续维持回撤档位
selected_interpretation: 当前无法区分，继续观察
confidence: 0.45
pass_condition: 无法取得同机构连续快照
```

```powershell
odds-journal scenario add matches/YYYY/MM/比赛.md --file scenario.yml
```

无法归类时使用 `unclassified`，没有稳定场景时使用：

```powershell
odds-journal scenario no-scenario matches/YYYY/MM/比赛.md --reason "资料不足，无法稳定归类"
```

### 5.4 案例检索

```powershell
odds-journal retrieve-cases matches/YYYY/MM/比赛.md --limit 10
```

案例回执冻结查询、时间边界、场景哈希、候选语料指纹、案例 revision、案例内容哈希和片段 ID。锁定前新增或修改合格案例会要求重新检索；锁定后新增案例不会使旧比赛失效。

### 5.5 分析与锁定

分析正文应按顺序记录：缺失信息、阶段性定位、理论盘口、实际时序、跨市场冲突、双向假设、区分触发条件、采用/排除规则、候选案例差异、主市场、次选、置信度和 Pass 条件。

```powershell
odds-journal lock matches/YYYY/MM/比赛.md `
  --market handicap `
  --selection away_handicap `
  --confidence 0.62
```

锁定冻结赛前事实、规则回执、场景、案例回执、分析正文和最终结论。之后任何赛前章节变化都会导致哈希失败。

### 5.6 临场与赛果

锁定后只向 `live-update` 追加带时间的新事实。新场景使用：

```powershell
odds-journal scenario add-live matches/YYYY/MM/比赛.md --file live-scenario.yml
```

比赛结束后使用 `finish` 记录结构化赛果；取消、腰斩或长期延期使用 `void`，不得把 void 纳入统计。

### 5.7 复盘和证据

```powershell
odds-journal prepare-review matches/YYYY/MM/比赛.md
odds-journal scenario resolve matches/YYYY/MM/比赛.md --file resolution.yml
odds-journal review matches/YYYY/MM/比赛.md --primary correct
```

复盘回执核对赛前锁定哈希、赛果、可信复盘指令、锁定时规则集和当前规则集。当前规则集只用于赛后参考，不得反向改变旧分析。

每个场景解析必须选择 `a`、`b`、`neither` 或 `unresolved`，并记录 `link_after_review`、`ineligible` 或 `defer`。比赛进入 reviewed 后，才允许追加证据：

```powershell
odds-journal evidence link `
  --rule-id dual-hypothesis-evidence `
  --ruleset-version 1.1.0 `
  --case-type match `
  --case-id MATCH_ID `
  --case-cluster-id MATCH_ID `
  --market handicap `
  --relation support `
  --target "是否完整保留双向假设" `
  --baseline "未执行双向假设流程" `
  --summary "本场流程执行完整" `
  --reviewed-by lcz `
  --eligible

odds-journal evidence report
```

同场多个场景保留多个事件，但晋级样本按 `case_cluster_id` 去重。概念规则看官方定义核验，方法和清单看执行完整率，经验规则才评估预定义目标、分母、基线、支持和反例。

## 6. 日常验收

```powershell
odds-journal source coverage
odds-journal case validate
odds-journal rules proposal-validate 1.1.0
odds-journal build-index
odds-journal validate --all
pytest
```

任何失败必须先修复再继续分析或发布。派生 JSON、报告和 SQLite 索引可以删除重建；原始资料、事件历史、已锁定比赛和已发布规则不能原地重写。
